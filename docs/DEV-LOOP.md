# 개발 자동화 루프

사람은 **방향만 정하고, 이상하면 멈춘다.** 나머지는 자동으로 돈다.

## 흐름

```
docs/BACKLOG.md  (작업 큐 — 위에서부터)
        │
        ▼
  Dev Loop  매일 03:00 KST
   1. 킬스위치 확인 (ops/automation.json)
   2. 맨 위 항목 1건만 집는다
   3. auto/<슬러그> 브랜치에 구현
   4. npm run lint && npm run build 통과할 때까지 반복
   5. PR 생성 (본문에 AUTOMERGE-OK 또는 NEEDS-REVIEW)
        │
        ▼
  자동 병합 판정  .github/scripts/automerge_check.py
   · 에이전트 자기 신고를 믿지 않고 실제 변경 경로를 다시 검사
   · 금지 경로 / 파일 15개 초과 / CI 실패 → 병합하지 않고 PR 만 남김
        │
        ▼
  main 병합 → 서버 auto_deploy 가 10분 내 배포 (CI 초록불 + 실패 시 자동 롤백)
```

```
Scout  매주 월요일 04:00 KST
   1. 측정 — 빌드 크기·응답시간을 재고 docs/metrics.json 과 비교 (LLM 안 씀)
      회귀하면 백로그에 자동 등록
   2. 정찰 — 백로그 미완료가 3건 미만일 때만 LLM 을 불러 새 결함을 찾는다
```

## 왜 서버가 아니라 GitHub Actions 인가

Lightsail 은 2GB 에 PostgreSQL·Next·PM2 가 함께 산다. 거기서 빌드까지 돌리면 메모리가 터진다 —
실제로 첫 자동배포가 빌드 단계에서 죽었고 `--max-old-space-size=1536` 을 걸어야 했다.
개발 자동화가 돌기 시작하면 빌드 빈도가 올라가므로 **운영 서버에서 빌드하면 안 된다.**

레포가 공개라 Actions 러너는 사실상 무료고, 4코어·16GB 라 빌드가 훨씬 빠르다.
서버는 이미 만들어진 것을 받아 띄우는 일만 한다.

## 토큰이 새지 않게 하는 장치

| 장치 | 값 | 이유 |
|---|---|---|
| 실행 빈도 | 개발 1일 1회 / 정찰 1주 1회 | 가장 큰 변수는 빈도다 |
| 1회 작업량 | **항목 1건** | 여러 개를 몰면 컨텍스트가 커지고 실패율이 오른다 |
| `--max-turns` | 개발 40 / 정찰 25 | 무한 반복 차단 |
| 잡 타임아웃 | 개발 30분 / 정찰 20분 | 매달린 실행을 강제 종료 |
| `concurrency` | 그룹당 1개 | 같은 항목을 둘이 잡는 낭비 방지 |
| 정찰 조건 | **백로그 3건 미만일 때만** | 이 조건 하나가 정찰 비용의 대부분을 없앤다 |
| 완료 항목 보존 | 지우지 않고 `## 완료` 로 이동 | 지우면 정찰이 같은 것을 또 찾아낸다 |
| 측정 | LLM 대신 스크립트 | "최적화 방법 찾아봐" 를 매일 LLM 에 시키면 같은 소리를 반복하며 토큰만 태운다 |
| 2회 실패 | `## 보류` 로 이동 | 무한 재시도 금지 |

## 멈추는 법

`ops/automation.json` 에서 해당 스위치를 `false` 로 바꿔 커밋한다. GitHub 웹에서 연필 아이콘이면 된다.

| 스위치 | 끄면 |
|---|---|
| `develop` | 매일 개발 루프 정지 |
| `scout` | 주간 정찰·측정 정지 |
| `enabled` | **전부 정지** (서버 자동화 포함) |

이미 열린 PR 은 그대로 남는다. 병합만 안 될 뿐이다.

## 자동 병합을 절대 안 하는 것

`.github/scripts/automerge_check.py` 의 `BLOCKED` 가 정본이다.

`db/migrations/` · `ops/` · `.github/` · `AGENTS.md` · `next.config.ts` · `package.json` · `package-lock.json`

`ops/` 와 `.github/` 가 들어 있는 이유는 **에이전트가 자기 안전장치를 고치지 못하게** 하기 위해서다.
이 경로를 바꾸려면 사람이 PR 을 보고 병합해야 한다.

`AGENTS.md` 4절(결제·환불 실행, 고객 발송, DB 파괴적 변경, 가격 결정)은 자동화에도 그대로 적용된다.

## 지금 막혀 있는 것

**서버 cron 이 멈춰 있으면 병합돼도 배포되지 않는다.** `ops/auto_deploy.sh` 를 cron 이 부르지 못하면
main 에 쌓이기만 한다. 개발 루프를 켜기 전에 서버 cron 부터 살릴 것.
확인: `ssh wolya "systemctl is-active cron; tail -5 ~/ops/logs/\$(date +%F).log"`
