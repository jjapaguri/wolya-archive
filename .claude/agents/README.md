# WOLYA ARCHIVE 역할 에이전트

이 폴더의 `.md` 파일 하나가 곧 "직원 한 명"이다.

## 조직도

```
              chief-of-staff   (총괄 — 입구)
                     │
      ┌──────────────┼──────────────┐
   builder       ops-manager     item-scout
  (코드 전부)    (재고·주문·CS)   (아이템 리서치)
```

| 파일 | 담당 | 주 실행 환경 |
|---|---|---|
| `chief-of-staff.md` | 요청 분해·순서 결정·위임·검수·보고 | 양쪽 |
| `builder.md` | DB 스키마·마이그레이션, API·인증·결제, 화면·컴포넌트, 배포 | Claude Code |
| `ops-manager.md` | 재고·주문·배송·CS 실무, 운영 리포트 | Claude Code (DB 접속 필요) |
| `item-scout.md` | 매입 후보 리서치, 시세·희소성, 상품 초안 | Cowork |

## ⚠ Cowork에서는 서브에이전트가 뜨지 않는다

`.claude/agents/` 는 **Claude Code(터미널)** 에서만 서브에이전트로 로드된다.
Cowork 클라우드 세션은 레포가 없는 빈 컨테이너에서 시작하므로 이 파일들을 자동으로 읽지 못하고,
"chief-of-staff한테 맡길게"라고 해도 실제 위임이 일어나지 않는다.

Cowork에서는 이 파일들을 **작업 진행 규칙**으로 읽고 직접 따르면 된다.
환경별로 무엇이 되고 무엇이 안 되는지는 `AGENTS.md` 1절 분담표가 정본이다.

## 쓰는 법 (Claude Code)

**1) 총괄에게 통째로 맡기기 — 기본**

```
> chief-of-staff한테 맡길게: 상품 상세 페이지에 사이즈별 재고 표시 붙여줘
```

총괄이 환경을 판단하고, 작업을 나눠 위임하고, 검수한 뒤 종합 보고한다.

**2) 역할 직접 지목 — 범위가 명확할 때**

```
> item-scout: 이 자켓 시세랑 상품 설명 초안 뽑아줘
> ops-manager: 오늘 주문 점검해줘
```

**3) 자동 라우팅** — 지목하지 않아도 요청과 각 파일의 `description` 이 맞으면 알아서 불린다.
그래서 `description` 은 "무엇을 하는가"가 아니라 **"어떤 요청일 때 이 역할을 불러야 하는가"** 로 쓴다.

## 왜 6명에서 4명으로 줄였나 (2026-08-18)

`db-manager` / `backend-dev` / `frontend-dev` → `builder` 하나로 합쳤다.

- 이 프로젝트의 작업은 대부분 **DB→API→화면을 한 번에 건드리는 수직 슬라이스**다
- 서브에이전트는 각자 **빈 컨텍스트에서 시작한다.** 층별로 3분할하면 코드베이스 파악을 3번 반복하고, 경계마다 정보가 샌다
- 순차 의존이라 **병렬 이득이 0**이다. 나누는 비용만 남았다
- 반면 `item-scout`(웹 리서치)와 `ops-manager`(운영 데이터)는 컨텍스트가 코드베이스가 아니라 진짜로 병렬이 된다

세 역할의 규칙은 하나도 버리지 않았다. `builder.md` 안에 **A. 데이터베이스 / B. 백엔드 / C. 프론트엔드**
섹션으로 그대로 있다. 코드베이스가 한 세션에 안 들어갈 만큼 커지면 그때 다시 쪼갠다.

## 규칙은 한 곳에만 쓴다

불변 규칙(금액·재고·스냅샷·웹훅·비밀값·완료 기준)과 승인 항목은 **`AGENTS.md` 가 유일한 정본**이다.
역할 파일에는 그 역할 고유의 것만 적는다.

> 이전 구조에서는 같은 규칙이 5개 파일에 복제돼 있었고, 실제로 어긋났다 —
> DB 구축 단계가 `chief-of-staff.md` 에는 5단계, `db-manager.md` 에는 4단계로 서로 달랐다.
> 지금은 DB 단계표 정본이 `db/README.md` 하나다.

## 역할 추가·수정

파일을 고치면 즉시 반영된다(재시작 불필요). 새 역할이 필요하면 같은 형식으로 `.md` 를 하나 더 만들고,
`chief-of-staff.md` 의 **휘하 역할** 표와 `AGENTS.md` 3절 표에 한 줄씩 추가한다.

역할을 새로 만들기 전에 먼저 자문한다 — **이 역할은 기존 역할과 컨텍스트가 겹치지 않는가?**
겹치면 새 역할이 아니라 기존 파일의 섹션이어야 한다.

## 안전장치

각 파일 맨 아래 **금지** 항목은 장식이 아니다.
사용자 승인이 필요한 전체 목록은 `AGENTS.md` 4절에 있다.
