# WOLYA ARCHIVE 역할 에이전트

이 폴더의 `.md` 파일 하나가 곧 "직원 한 명"이다.
Claude Code(터미널)와 Cowork 양쪽에서 이 정의를 읽어 해당 역할로 동작한다.

## 조직도

```
                    chief-of-staff  (총괄 비서 — 입구)
                            │
        ┌──────────┬────────┼────────┬──────────┐
   db-manager  backend-dev  frontend-dev  ops-manager  item-scout
     (DB)        (서버)       (화면)      (재고·주문)   (아이템 리서치)
```

## 쓰는 법

**1) 총괄에게 통째로 맡기기 (기본)**

```
> chief-of-staff한테 맡길게: 상품 상세 페이지에 사이즈별 재고 표시 붙여줘
```

총괄이 db → backend → frontend 순서로 알아서 연쇄 위임하고, 각 단계 결과를 다음 단계에
넘긴 뒤 마지막에 종합 보고한다.

**2) 역할을 직접 지목하기 (범위가 명확할 때)**

```
> item-scout: 이 자켓 시세랑 상품 설명 초안 뽑아줘
> ops-manager: 오늘 주문 점검해줘
```

**3) 자동 라우팅**

역할을 지목하지 않아도 요청 내용과 각 파일의 `description`이 맞으면 Claude가 알아서 해당
에이전트를 부른다. 그래서 `description`을 "어떤 요청일 때 부르는지" 중심으로 써 둔 것이다.

## 연쇄 실행의 전제

서브에이전트는 **각자 빈 컨텍스트에서 시작한다.** 지금 이 대화를 보지 못한다.
그래서 `chief-of-staff`의 규칙 4·5(컨텍스트를 통째로 넘기고, 앞 단계 결과를 다음 프롬프트에
붙여 넣는다)가 이 시스템 전체의 핵심이다. 이게 빠지면 연쇄가 아니라 그냥 따로 노는 6명이 된다.

## 안전장치

각 에이전트 파일 맨 아래 **금지** 항목은 장식이 아니다. 특히 아래는 어떤 역할도 자기 판단으로
실행하지 않고 사용자 승인을 받는다.

- 프로덕션 DB 파괴적 변경 (DROP / DELETE / TRUNCATE)
- 실제 결제·환불 실행
- 고객에게 나가는 메시지 발송
- `main` push, 서버 재배포(`~/deploy.sh`)
- 가격 인하·프로모션 결정

## 역할 추가·수정

파일을 고치면 즉시 반영된다(재시작 불필요). 새 역할이 필요하면 같은 형식으로 `.md`를 하나 더
만들고, `chief-of-staff.md`의 **휘하 역할** 표에 한 줄 추가한다.

`description`은 "무엇을 하는가"보다 **"어떤 요청일 때 이 역할을 불러야 하는가"**를 쓴다.
자동 라우팅 정확도가 여기서 갈린다.
